## 2. 变更与兼容性

- `document_access` 按 `(document_id, owner_key)` 维护归属；同内容可分别授权给多个账号。设备绑定账号时迁移独立设备的归属。登记失败释放本次文档解析配额。
- 无归属的历史文档保持 404，不能开放旧 ID 读取接口。用户须主动重新上传字节一致的原文件；两端在本地验证内容摘要，恢复只消耗文档解析额度，不生成学习包。
- 新增 `ws_tickets` 表及过期索引，启动时自动创建；只存 HMAC，60 秒、一次性、SQLite 事务原子消费，签发响应不缓存。过期在获得写锁后重新判断。
- 新增 `POST /v2/lecsync/realtime/ticket`，使用 HTTP Bearer、账号校验、设备及全局限流。WebSocket 仍支持 Authorization 与 bearer 子协议；URL 仅用 `ticket`，出现 `access_token` 参数即拒绝。
- 浏览器首连/降级/重连分别取新 ticket；等待结果时停止或开始另一课堂，旧响应不得重连新课堂。
- 功能变更未涉及 Android Room schema；后续发布已另获用户批准升为 V2.0.11 / code 13，包名和签名证书不变。Debug APK 仍不是公开分发的发布 APK；当前已发布签名 Release 的证据见上方。

4. 验证 WSS 首次 ticket 可用、重放/过期/伪造 4401，设备 token 不能冒充 ticket；URL `access_token` 即使配合合法 Bearer 也必须拒绝（合法 Bearer 本身不应放 URL）。
5. **再网页版**：新页面依赖 ticket 接口，不能先于新网关发布。原有静态缓存或长开页面可能需要刷新；保留旧哈希资源，避免正在加载的旧页面断资源。
6. 微信、桌面浏览器按第 1 节执行短时合成验收，检查停止后音频/WS 资源释放、重连使用新 ticket。负责人决定是否进行需真实上游的验收并控制额度，自动化不调用生产付费模型。
7. 文档验收：老记录 404 → 用户确认上传同一原文件 → 200；异账号仍 404；选错文件不覆盖；归属失败不扣配额。
8. Android 发布由负责人另行确认版本号、签名、arm64 真机验收、APK 校验和及官网版本一致性；网页上线不意味着 APK 已发布。
9. 观察新错误码、连接失败率、异常配额、响应耗时及用户反馈；记录观察窗口和负责人。任何越权或停止后继续采集应立即暂停入口并启动安全回退。

## 5. 安全回退（不能简单恢复已知漏洞）

**回滚是恢复服务，不是重新开放文档越权或长期 URL token。**

- 网页版单独出错：可先回退到已确认不使用 URL 长期 token 的旧静态版本，保留新服务端及权限修复。微信兼容功能可能暂时不可用，需明确告知。
- 服务端出错：先停用新功能入口/保护写入，再同步回退配套网页版。新网页版不能留在没有 ticket 接口的旧网关上。
- 服务端回退目标必须仍保留文档归属检查与禁止 URL 长期 token。旧 R22 若缺少这些安全修复，不能直接裸回滚开放相关接口；优先修复前进，或使用事先准备并验证过的安全回退构建。必要时由负责人暂时关闭受影响文档/实时接口。
- 新增 `ws_tickets` 表是加法迁移，通常不需要删表或回退数据库；保留新 `document_access` 数据。不要为回滚代码而把数据库恢复到旧快照，否则会丢失发布后的用户数据、额度和授权。
- 若确需恢复数据库，由负责人停写、备份当前状态、说明数据损失窗口并单独批准；不能自动覆盖。
- 回退后重复健康、账号、旧 App、权限隔离、WS 鉴权与停止操作验收。保留失败版本和日志在隔离区用于定位，不做永久删除。
